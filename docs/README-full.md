# 岁语 · 陪老人说话的智能体

一个网页上就能用的智能体：**它当老人的孩子，细心应答；老人讲的话被整理简化后存进数据库；老人再提起相关内容时，它去搜主句库把话答上来。**

数据存在本机 **MySQL** 里，一个账号一位老人，账号之间完全隔离；第一次用先注册，之后老人端、大屏查看端、家人远程端都要登录。

需要：**Node.js ≥ 20**、**MySQL 8**（`D:\mysql` 便携版可自动拉起）、`npm install` 装过依赖。

> 库里没有任何预置内容。**第一条记录一定来自老人真实说出的那句话。**
> 它也不会编造 —— 库里没有的，它会说"记不清了"，然后请老人讲。

## 怎么跑

### 最省事：双击启动

**双击 `start.bat`**。

它会：找 node → **没开 MySQL 就先拉起 MySQL** → 起服务（后台，不弹黑窗口）→ 等就绪 → **自动打开浏览器** → 自己关掉。
从双击到能说话，大概 3～10 秒（第一次开数据库会慢一点）。

第一次打开会先看到**登录 / 注册页**。注册一个账号，之后这个账号里的记忆、照片、吃药、记事本都只属于它。

要停就**双击 `stop.bat`**。

| 文件 | 干什么 |
|---|---|
| `start.bat` | 起 MySQL（如未开）+ 起服务 + 开网页 |
| `stop.bat` | 停服务（连同它拉起的 Python 子进程一起收掉；MySQL 不动） |
| `start.ps1` | 启动的完整逻辑（`start.bat` 只是转到它） |
| `stop.ps1` | 停止的完整逻辑 |

> `stop.bat` 不只看 `data\seyo.pid`：手动 `npm start` / `node src/server.mjs` 起的服务没有 pid 文件，
> 它会按 **3789 端口**找到进程、确认是岁语再停（顺带收掉 3791/3792/3793 上它拉起的 Python 子服务）。
> **改过代码一定要重启服务** —— 已经在跑的旧进程不会自己加载新代码，只刷新网页是看不到后端改动的。

启动时会检查这几件事，有问题直接说清楚：

- **node 版本** —— 要 ≥ 20（MySQL 驱动和 ESM 都要）
- **MySQL** —— 3306 没开会尝试自动拉起 `D:\mysql`；起不来会提示先双击 `D:\mysql\启动MySQL.bat`
- **Python 有没有 vosk + torch** —— 没有只会警告，打字说话照样能用（语音/表情是懒加载的）
- **端口被占** —— 会说"被别的程序占着"
- **已经在跑** —— 不重复起，直接开网页

日志在 `data\server.log`，PID 在 `data\seyo.pid`。
启动/停止都能带参数：`start.bat -NoBrowser`（只起服务不开网页）、`start.bat -Port 3790`、
`stop.bat -Port 3790`。

> ⚠️ `.bat` 文件**必须保持纯 ASCII** —— cmd.exe 用 OEM 编码解析批处理，
> 里面塞中文会导致命令被读错。所有中文都在 `.ps1` 里（UTF-8 **带 BOM**，不然 PowerShell 会当 ANSI 读）。
> 这两个坑都踩过，别动。

### 或者命令行

```bash
cd seyo
npm install         # 第一次：装 mysql2
node src/server.mjs --port 3789
```

浏览器打开 **http://127.0.0.1:3789/**，先登录/注册，再开始说话。

* 按住左边的大话筒说话 —— **在本机转文字，录音不出门**（Vosk，见下）
* 或者直接在输入框打字（任何浏览器都能用）
* 岁语会用系统语音把回答念出来。不想听：**👤 账号 → 设置 → 声音**关掉（默认是开的）

> **刷新不会丢对话**：页面会把会话 id 记在浏览器 `localStorage` 里，刷新后从服务端
> 把最近 **10 条**对话摆回来，也不会重复说一遍欢迎语。
> 换账号 / 退出登录时会清掉会话 id，不会把上一个账号的聊天带过来。

> 浏览器有个限制：页面还没被点过的话，第一句往往不出声。
> 以前是浮一个"点一下，让岁语出声"的按钮让老人去找它 —— 现在改成
> **页面里第一次点击/按键就自动补上声音**，他按话筒、点设置、点空白处都算数。

自测（会先把**测试账号**的库清空，然后按你要的四件事逐条验证；需要 MySQL 已启动）：

```bash
npm test
```

## 账号与 MySQL

### 登录 / 注册

第一次打开页面会跳到 **`/login`**：

- 没有账号 → 点「注册新账号」（用户名 2–20 个字，密码至少 6 位）
- 已注册 → 登录
- 登录后老人端（`/`）、大屏查看端（`/family.html`）和家人远程端（`/remote.html`）用同一个账号
- 三个页面都要登录；会话 Cookie 默认 **30 天**，过期后重新登录
- 顶部导航都有 **👤 账号** 入口：点开是一个弹窗，两个页签
  - **账号**：当前用户名、改密码、退出登录
  - **设置**（老人端）：声音、用什么念、嗓音、摄像头、全屏、内部过程（原来右上角的设置面板也并到这里）
  - **设置**（家人端）：全屏、修改基本信息、重置这位老人的数据
  - **设置**（远程端）：修改基本信息、重置这位老人的数据（远程端不需要全屏）
- **全屏默认打开**：`start.bat` 会用 Edge / Chrome 的 `--start-fullscreen` 直接全屏打开；
  这是**浏览器窗口级全屏**，在老人端和查看端之间切换页面不会退出全屏。
  没有这两个浏览器或手动刷新页面时，第一次点击/按键会自动补全屏；设置里可以关掉
- **全屏下切换页面**：如果是从页面按钮进入的网页全屏，切换会用同源 iframe 留在当前文档里，
  全屏不会退出；地址栏暂时不变，退出全屏后恢复正常跳转
- 改密码要输旧密码；改完其它设备上的登录会失效，当前这台继续用
- 三个页面的账号弹窗共用同一套样式与账号表单；「设置」页签内容按页面职责不同

**一个账号 = 一位老人。** 老人端和家人端看到的是同一份该账号的数据。

### 第一次用：老人端补基本信息

新账号第一次打开老人端时，如果还没填过 **称呼 / 出生年份 / 老家**，会直接弹一个
「先跟岁语说一声」的卡片：

- 填了之后岁语知道该怎么称呼、年份和老家也能对上；
- 点「保存」写进当前账号的资料；
- 点「以后再说」只关掉这次，下次打开还会再问（也可以在家人端「账号 → 设置 → 修改基本信息」里填）。

**第一次开口先自我介绍**：新账号还没有任何对话记录时，岁语会先说
「爷爷，我是岁语，您的小孙子。往后我就在这儿陪您说说话。」，不会一上来就问问题；
之后的开场白才恢复正常寒暄。

### 家人远程端 `/remote.html`

给孩子的手机/另一台电脑用，和老人端、大屏查看端**完全分开**——它没有回老人端或大屏查看端的链接，只能单独收藏/打开。

- **同一台电脑**：`http://127.0.0.1:3789/remote.html`
- **手机 / 另一台电脑**：`start.bat` 现在监听局域网，打开
  `http://<这台电脑的局域网 IP>:3789/remote.html`；第一次可能要在 Windows 防火墙里允许 Node。
- **心情提醒**：老人情绪低落/不安时，页面顶部会出现提醒（以前是隐藏的），可以马上发消息或打电话。
- **和家人说话**：
  - 孩子在远程端发消息 → 老人端轮询到后，**岁语直接念给老人听**（老人端没有任何聊天按钮）
  - 老人说「**岁语，我要和孩子说话**」→ 岁语问「您想跟孩子说什么？」→ 老人下一句就发给远程端
  - 也可以说「算了/不说了」取消
  - 岁语拟好一句回复后，老人说「**就这样子回**」→ **AI 判断确认后真正发出去**，不会再只嘴上说“回了”
  - 老人直接下指令也行：「**那给他回一个你好**」「回他一句我挺好」「**给小陈发个你好**」「给老二回一句…」→ AI 判断这是要发消息，提取内容后真正写库；孩子的大名、小名、昵称都可以
  - **第一次用某个名字/小名**（如“小陈”）时，岁语会先问「小陈是您的孩子吗？」；老人确认“是”后记住这个名字，以后直接发，不再重复问
  - 消息存在 MySQL 里，**远程端刷新不会丢**；孩子的话也会补进老人端的最近对话，老人端刷新后还能看到
  - 最近的孩子消息会带进岁语的上下文；老人问「孩子有没有发消息 / 说什么了」会按真实消息回答，**不会再说“我这儿看不到手机”**
- **今天的对话总结**：按天生成，写成**一段整体总结**，只挑重要的 2～4 件事；
  写的时候明确区分**老人 / 岁语 / 用户（家人）**分别说了什么、做了什么，但不用分三段列标签。
  有模型用模型，没模型用当天数据兜底。孩子可以**点赞 / 回复**，点赞和回复会通过岁语同步告诉老人。

**注意**：远程端没有「回老人端」的入口；登录过期后会回到登录页，登录成功后仍回到 `/remote.html`。

### 数据隔离

每个账号一个**独立的 MySQL 数据库**：

| | |
|---|---|
| 主库 | `seyo` —— 只放 `users` 和 `sessions`（账号、会话） |
| 账号库 | `seyo_u_<账号id>` —— 这位老人的记忆、照片、吃药、记事本全部在这 |
| 账号间 | 互相看不到；接口一律按登录账号切库，未登录返回 401 |

### MySQL 连接

默认连本机 **`127.0.0.1:3306`，用户 `root`，密码 `123456`，主库 `seyo`**（跟 `D:\mysql` 便携版的说明一致）。
要改就编辑 `data/mysql.json`（不存在会按默认值连），或设环境变量：

```json
{ "host": "127.0.0.1", "port": 3306, "user": "root", "password": "123456", "database": "seyo", "prefix": "seyo_u_" }
```

`start.bat` 发现 3306 没开时，会尝试用 `D:\mysql\my.ini` 自动拉起 MySQL；起不来会提示你双击
`D:\mysql\启动MySQL.bat`。`stop.bat` **不会**停 MySQL（可能还有别的程序在用）。

首次启动会自动建主库、账号表和每个新账号的库表，不需要手工执行 SQL。
旧的 `data/seyo.db`（SQLite）不再读取，留着当备份；本次没有把旧数据迁进 MySQL。

### 登录页测试

跑页面自测（`test/family.mjs`、`test/nav.mjs`）时，脚本会自动用固定测试账号
`seyo_test_user / 123456` 注册或登录，不需要你手动开浏览器。
`test/run.mjs` 用独立的 `seyo_test` 账号库，不会碰真实账号的数据。
其余 Chrome 自测（`test/settings.mjs` / `sound.mjs` 等）没有自带登录 Cookie ——
要么用 `set SEYO_AUTH=off` 再起服务，要么先手动登录浏览器再跑。

## 智能体：说话交给提示词工作流

对话的"大脑"在 [`src/prompts.mjs`](src/prompts.mjs)、[`src/agent.mjs`](src/agent.mjs) 和 [`src/understand.mjs`](src/understand.mjs)。
**怎么理解老人、怎么切句、情绪是什么、人物/地点/时间/事件是谁、记什么、怎么说话，全部交给模型判断**；
本地引擎只负责检索、去重、真正入库，以及时间轴 / 图谱 / 地图的结构化存储。想改判断方式，改中文提示词就行。

```
老人说一句话
     │
     ├──[理解节点]  understand()  切句 + 情绪 + 人物/地点/时间/事件
     │                             + 意图 + 是否值得记 + 润色
     ├──[主对话节点] agentReply() 人格 + 整理后的记忆 + 多轮历史 → 回复
     └──[主动开口节点] agentOpening() 拿整理后的记忆现起个话头
```

两个说话节点在 `agent.mjs` 里，理解判断在 `understand.mjs` 里，提示词全文在 `prompts.mjs` 里。

**主对话里的「160 条记忆」是什么**：
是 MySQL `sentences` 表里**整理好的主句**（每条含陈述句、润色版、时间、人物、地点、事件、置信度），
不是 `utterances` 里的全部原始对话记录。模型看到的是最近 160 条整理后的记忆 + 最近 8 轮对话 +
最近 5 条孩子消息；原始对话只作为档案保留，不会整段塞进提示词。

**和归档的分工**：切句、情绪、实体判断由模型给；**去重、关联入库、四维表仍走本地引擎**
（`engine.mjs` 的 distill / attachDimensions）。所以家人端的时间轴、图谱、地图照常有数据。

### 偶尔主动引他讲讲以前的事（约 10% 的轮次）

不是每一轮都问 —— 那样像查户口。大约 **10% 的轮次**，岁语在正常回话之后会顺带把话头引到
**他以前的一件事**上，而且是像 **"您小时候有什么好玩的事儿吗？"** 这样**开放地问**，
引他说**新的**往事。

- **不是把库里已经记着的话再问一遍**（不说"您上回说…"），是请他讲还没讲过的；
- 方向池里有 10 个：小时候 / 上学 / 年轻时头份工作 / 跟老伴成家 / 孩子小时候 / 老伙伴 /
  过年过节 / 吃的 / 玩的 / 老家；
- **哪块讲得少就先问哪块**（按已归档记忆里的关键词估覆盖），最近问过的方向不再连着问；
- 只问一个小问题、不说教、不替他补人名地点年份 —— 他不知道的，就等他说；
- **这些时候不引**：陪伴模式（情绪不高只陪着）、老人身体不舒服、请求句 / 改口 / 补充细节、
  情绪 low / uneasy —— 那时候先办正事、先照顾情绪。

概率在 [`src/engine.mjs`](src/engine.mjs) 的 `INVITE_MEMORY_RATE`（默认 `0.1`），
方向池在同文件的 `INVITE_TOPICS`，这一轮的引导话术在 [`src/prompts.mjs`](src/prompts.mjs)
的「这一轮：顺带引他讲讲以前的事」。

### 提示词里重点防的几件事

写提示词最费劲的不是"让它会说"，是"防它乱说"。这几个坑都踩过并写进了提示词：

| 坑 | 它本来会说 | 现在会说 |
|---|---|---|
| 顺手编个具体名字 | "记得啊，**育才小学**嘛" | "这我真不知道，您念的哪个小学？" |
| 从语气推断生死 | "秀兰奶奶**走了**有些年头了吧" | "嗯……想她了。" |
| 问句里夹带没说过的具体事 | "您跟老张**下棋**那事儿谁赢了？" | "您跟老张最近还联系吗？" |
| 开场白编个症状 | "上次说**腰疼**，好点没？" | "爷，今儿中午吃的啥？" |
| 开场白每次一样 | 6 次里 5 次同一句 | 换着角度问（存了最近说过的） |

**一条分界线**：过去的事（人、地点、时间、发生过什么）**一个字都不能编**；
当下的寒暄（吃了没、天冷不冷）可以说，但别假设太具体的东西。
没有这条线，智能体要么乱编，要么干巴巴只会问"吃了没"。

> 深度调试过这套提示词的独立版本在 [`../sunzi/`](../sunzi)，
> 那边的 README 记录了完整的踩坑过程。

## 陪伴守望：不用老人开口，它自己会过来

两个触发条件，都由 [`src/watch.mjs`](src/watch.mjs) 判断：

| 触发 | 条件 | 岁语说什么 |
|---|---|---|
| **情绪低落** | 摄像头看出老人没精神（或聊天文字里听出来） | "爷爷，我来了。您歇着，我坐这儿陪您。" |
| **太久没说话** | 超过 **2 小时**没人说话 | "爷爷，我来了。给您倒杯热水，暖暖手。" |

说什么是 [`prompts.mjs`](src/prompts.mjs) 里的 `buildCheckInMessages` 生成的，两条铁律：

1. **绝不提"我看到""我注意到"** —— 你是孙子，不是监控。
   所以聊天里不会出现"看您好像不太高兴"这种话（虽然确实是看出来的）。
2. **不问问题。一个问号都不要有。** 老人心里不痛快，再抛问题只会更累。
   模型偶尔不听话，`agent.mjs` 里还兜了一层：出现问号就砍掉问句。

### 两个节奏，别搞混（看脸 vs 说话）

**看脸**和**说话**是两回事 —— 看脸只管"看"，不打扰人；说话要过一道道闸门，慢得多。

| | 值 | 干什么 |
|---|---|---|
| **看脸**（人脸识别） | **15 秒**（情绪不对时 5 秒） | 盯表情，**只负责看** |
| **主动开口**（说话） | **最快 5 分钟一次** | 真的张嘴说话，由 `debounceMs` 兜底 |
| 　└ 第一次发现情绪不对 | **不等** | 最该立刻开口的时候，不受 5 分钟限制 |
| 　└ 闲置搭话 | 10 分钟（`minGapMs`） | 太久没人说话才过去看看 |
| 　└ 一直难过重复 | 10 分钟（`sadRepeatMs`） | 他一直闷着，过一阵再说一句 |

⚠️ **这两个数以前都是 15 秒**，摆在一起会让人以为"每 15 秒就可能说一句"。
其实说话还有更严的闸门压着。现在分开成 15 秒 / 5 分钟，一眼看得出区别。

### 不唠叨

- **主动开口最快 5 分钟一次**（第一次发现情绪不对时不等 —— 那时候最该立刻开口）
- 闲置搭话、一直难过的重复安慰，各自 **10 分钟**一次
- **晚上 22 点到早上 7 点不打扰**
- 老人一开口，闲置计时立刻清零
- **「🤝 安静模式」开着 → 一句主动的话都不说**（见下）
- 内部过程 → ⑤ 陪伴守望 里能看到"闭嘴多久、再过几分钟会主动搭话"；
  调试时写进去的异常节奏，可以点 **「恢复默认节奏」** 拉回来（接口 `DELETE /api/watch/config`）。

### 安静模式（老人自己按的）

页面上那个 **🤝 安静模式** 按钮。打开之后**守望完全不主动开口**：

- 看出他情绪不好 —— 不说
- 两个钟头没动静 —— 也不说

**老人想说话时自己按话筒或打字，那时候照常回。** 这条只管"主动开口"，
不影响应答 —— 它压过**所有**其它触发，因为「安静模式」的意思就是"你在这儿待着就行"。

这个状态会告诉服务端（不然守望照样开口），并且记在 `localStorage` 里，
刷新之后还在。别跟 `quietFrom/quietTo`（夜间静默，到点自动静音）搞混。

⚠️ 注意引擎里还有个同名的 `companion`：那是"他情绪不高，接下来 10 分钟只陪着、不问事"
的**临时**状态，由情绪自动触发。跟这个按钮是两回事，前端分别记在 `S.quiet` 和 `S.companion` 里。
（以前脚本把两者混用了，结果他只要回一句话，安静模式就被悄悄关掉。）

### 吃药提醒

**家人查看端 →「💊 吃药提醒」页签** 里设定：吃什么药、每次吃多少、**每天几点吃**（可以写多个时间 `08:00,20:00`）、备注（饭后/随餐）。老人端（展示端）只负责提醒，屏幕上不放设置入口。

- **提前 10 分钟**就开始提醒，不是卡到正点才喊 —— 老人找药、倒水都要时间；
- 老人端到点弹一张大卡片（药名 / 时间 / 剂量 / 备注），岁语同时开口念一遍；
- **没按「我吃过了」，每 5 分钟再提醒一次**，卡片一直挂着 —— 直到确认；
- 不想马上吃可以点「10 分钟后再提醒」：只把这一顿暂时压住，**不算吃过**，10 分钟后接着提醒；
  压住的时间记在浏览器里，**刷新 / 重开页面也不会立刻再弹**；
- 确认只记「这顿」（药 + 日期 + 时间）：吃过 8 点那顿，不会把 20 点那顿也标成吃过；
- 老人端顶上有一条「今天的药」，一眼能看到今天几顿、下一顿还差多久；
- 家人端「今天的药」里能看到每一顿的状态（已吃过 / 到点了还没吃 / 快到点 / 还没到），也可以替老人点「标记吃过」。

数据在 `meds` / `med_logs` 两张表里：`meds` 是"每天几点吃什么"，`med_logs` 记哪一顿已经确认吃过。
家人端 **账号 → 设置 → 重置这位老人的数据** 会连吃药安排和记录一起清掉（同时清记忆、对话、照片、基本信息）。

> 老人端页面得一直开着（展示端/kiosk 本来就是常开的）。关掉网页就不会响 —— 提醒不是手机推送。

### 记事本 / 到点提醒（老人端）

直接跟岁语说：**「5 分钟后提醒我关火」**，她会应下来，服务端开始倒计时；到点老人端弹一张大卡片并开口念一遍，点「知道了」才收。

- 相对时间都认：`5 分钟后` / `半小时后` / `一个小时后` / `一刻钟后` / `过 10 分钟`；
- 钟点也认：`明天早上 8 点提醒我关火` / `晚上八点半提醒我`；
- **计时在服务端**：页面关掉、切到后台都不影响；回来一刷新，到点就会弹；
- 老人端多了个 **📒 记事本** 按钮：能看到还没到点的提醒、还剩多久，也能删掉；
- 点「知道了」才算完成；没点之前一直挂着（刷新也还在）；
- 「重置」会连记事本一起清空。

数据在 `reminders` 表；老人端每 5 秒轮询一次 `GET /api/reminders`。

#### 为什么用 HSEmotion 而不是自己训的那个

刚开始用的是本项目自己训的 ResNet18+CBAM（FER2013）。换掉是因为**实测下来它在没见过的数据上差太多**：

| | FER2013 test（它的训练分布） | **RAF-DB test（没见过的）** |
|---|---|---|
| 自训 ResNet18+CBAM | **67.0%** | 45.4%（sad 只有 64%） |
| HSEmotion | 50.8% | **63.5%（sad 88%）** |

FER2013 那一列是自己划的重点，RAF-DB 那一列才是「换批人脸还准不准」。
真实摄像头拍到的老人，更接近 AffectNet 那种随手拍，不是 FER2013 的 48×48 灰度高糊。

按实际用的「消极 / 正常 / 积极」口径（FER2013 test 770 张）：

```
自训模型   消极≥.65              →  负面召回 79%   happy误报 2%   neutral误报 32%
HSEmotion  消极≥.65 且积极≤.22   →  负面召回 77%   happy误报 4%   neutral误报 28%
HSEmotion  在 RAF-DB 上          →  负面召回 90%   sad召回 95%
```

**装法**：`pip install hsemotion-onnx`（权重自动下到 `~/.hsemotion_onnx/`，15 MB）。
⚠️ 别装 `hsemotion`（PyTorch 版）—— 它把整个模型 pickle 了，绑死当年的 timm 版本，
跟现在的 timm 不兼容，会报 `'DepthwiseSeparableConv' object has no attribute 'conv_s2d'`。

**想切回自训模型**：启动时加 `--provider own`，或者设环境变量 `FER_PROVIDER=own`。
两个后端都留着，随时可切。

#### 8 类表情 → 岁语的心情四档

```
P(难过) ≥ 45% 且 消极合计 ≥ 50%            → low     难过
消极 ≥ 65% 且 积极 ≤ 22% 且最大类是消极     → uneasy  看着不太对劲（生气/烦躁/害怕）
积极 ≥ 50% 且最大类是 happy/surprise       → happy   心情不错
其余                                       → normal  平常
```

阈值是在真实数据上标定的，不是拍脑袋。
`low` 和 `uneasy` 都会触发主动关心，但**回话方式不一样**：
难过要安慰（说出他心里那个滋味），不太对劲只要"不打扰的在场"（别猜原因、别问）。

#### 检不到人脸怎么办

先补一圈边再检一次（「整张图就是一张脸」这种零边距裁剪，YOLO 容易漏）；
还检不到就**退回整图识别**，而不是一个字都不给。返回值里带 `uncertain` 标记。

**默认就是开的**：打开页面会自动开摄像头，浏览器第一次会弹一次权限框，允许过之后就是静默生效。
不想要的话在**👤 账号 → 设置 → 摄像头**里关掉 —— 关过之后就不再自动开了（记在 `localStorage` 里）。

**换模型**：**👤 账号 → 设置 → 内部过程**里能改模型目录。把新训练的 `final_best.pth`
放进那个目录的 `weights/` 下，点「重新加载模型」就行。

### 说话：本机神经网络 TTS（文字和声音都不出门）

两条路，设置里能切：

| 引擎 | 默认 | 是什么 |
|---|---|---|
| **本机神经网络** | ✓ | sherpa-onnx + `vits-zh-hf-fanchen-wnj`（**中文男声**） |
| 系统语音 | | 浏览器自带的 `speechSynthesis`（Windows 那几个老嗓音） |

**为什么不用浏览器自带的**：Windows 上能选的中文本地嗓音就 `Huihui`（女）、
`Kangkang`（男）、`Yaoyao`（女）三个，全是 2010 年代的拼接语音 —— 男声对了但音质很硬、
腔调不自然。神经网络 TTS 明显好一档。

| | |
|---|---|
| 引擎 | **sherpa-onnx 1.13.8**（`model/tts_service.py`） |
| 模型 | `vits-zh-hf-fanchen-wnj`，**115 MB**，中文男声 |
| 接口 | `POST /api/say` → 直接回 WAV → 前端 `<audio>` 播 |
| 本机推理 | **断网可用**，文字和声音一个字节都不出这台机器 |

**装法**：

```bash
pip install sherpa-onnx
# 模型（115 MB）解压到 model/tts/ 下
curl -LO https://github.com/k2-fsa/sherpa-onnx/releases/download/tts-models/vits-zh-hf-fanchen-wnj.tar.bz2
tar xf vits-zh-hf-fanchen-wnj.tar.bz2 -C model/tts/
```

Node 会像管表情/语音识别服务那样**懒加载**它（第一次要说话才启动，退出时一起收掉），
日志在 `data/tts.log`。

**代价**：合成不是白来的 —— 一句话要先合成完才能播，几百毫秒到一两秒。
所以设置里保留了「系统语音」这条退路：立刻出声，音质一般。老机器跑不动时切回去。

**如果本机合成起不来**（没装 sherpa-onnx / 模型没下），前端会**自动退回系统语音**
并在设置里写明原因，不会让老人干等。

### 系统语音那一路：为什么默认是男声

岁语是**小孙子**，所以默认挑男声。

**踩过的坑**：原来写的是

```js
const want = [/Xiaoxiao/, /Xiaoyi/, /Yunxi/, /Huihui|Yaoyao|Kangkang/, /zh-CN/, ...];
```

`vs.find()` 会按浏览器给的**数组顺序**扫到第一个匹配的。这台机器上中文嗓音依次是
`Huihui（女）`、`Kangkang（男）`、`Yaoyao（女）` —— 所以 `Huihui` 永远先中，
**Kangkang 根本没机会**，一直是女声。

现在改成男声优先 + 女声黑名单：

```js
voice = pool.find(v => MALE_VOICE.test(v.name))        // Kangkang / Yunxi / 云希 …
     || pool.find(v => !FEMALE_VOICE.test(v.name))     // 认不出性别的
     || pool[0];
```

**音调也调回来了**：原来 `pitch = 1.1` 是把音调**抬高**，听上去发尖、更不自然，
而且会让本来低沉的男声也变娘。现在是 `pitch = 1.0`、`rate = 0.95`。

**设置里能自己挑**（设置 → 声音 → 系统语音用哪个嗓音）：

```
Microsoft Huihui  … （女）
Microsoft Kangkang … （男）   ← 默认选这个
Microsoft Yaoyao  … （女）
Google 普通话（中国大陆）〔要联网〕
```

- 标出**男女** —— 浏览器只给名字不给性别，靠名字认
- 标出**要联网** —— Chrome 会塞几个 Google 的嗓音，那些会把文字发给 Google，
  跟这个项目"文字不出门"的底线冲突，所以默认只挑本机嗓音

### 语音识别（本地 Vosk，录音不出门）

按住话筒说话，文字在**本机**转出来。

**为什么不用浏览器自带的那个**

一开始用的是 `webkitSpeechRecognition`。它有个要命的问题：
**会把录音传到 Google / 微软的服务器**再返回文字，而且必须联网。
这跟这个项目的底线是冲突的 —— 老人家里说的话，
不该为了转成文字就先寄出去转一圈。断网时它也直接不能用。

现在浏览器只负责录音，转文字交给本机的 Vosk：

| | |
|---|---|
| 引擎 | **Vosk**（`model/asr_service.py`） |
| 模型 | `vosk-model-small-cn-0.22`，**42 MB**（大模型 1.3 GB，低配机器扛不住） |
| 录音链路 | `getUserMedia` → `AudioContext` → 重采样 16 kHz → 16 位 PCM → `POST /api/listen` |
| 本机推理 | **断网可用**，录音一个字节都不出这台机器 |

**装法**：

```bash
pip install vosk
# 模型下到 model/asr/ 下（脚本会自动找这个路径）
curl -LO https://alphacephei.com/vosk/models/vosk-model-small-cn-0.22.zip
unzip vosk-model-small-cn-0.22.zip -d model/asr/
```

Node 会像管表情服务那样**懒加载**它（第一次按话筒才启动，退出时一起收掉），
日志在 `data/asr.log`。

**自测**（用 Windows 自带中文 TTS 生成语音，再喂回来比对）：

```bash
python test/asr_test.py
```

**权衡**：本地小模型的识别率不如大厂云端。老人说的话短、语速慢、词汇窄，
小模型够用；真觉得不行，可以换 `vosk-model-cn-0.22`（1.3 GB，更准，但更慢）。

家人端会同步显示：老人最近情绪怎么样、多久没说话了。只在**值得留意时**才显示，
平时不打扰。

## 四个能力，分别落在哪里

### 一、当作老人的孩子，细心回答

* 先说一句接住情绪的话，再回答，**一次最多问一件小事**（"那是在哪儿的事呀？"）
* 单句长度可控（人设里的 `max_chars`，默认 60 字），语速放慢到 0.92
* 不说教、不评判、不给医疗建议；连着两轮不会用同一句开场白
* 界面按适老化做：对话正文 26px、对比度 > 4.5:1、可点元素 ≥ 48px、没有需要老人点的菜单

**情绪跟不上就不问了**：识别到低落（叹气、消极词、多轮敷衍）就切到陪伴模式，不提问、不索取回忆、连"我记着了"都不说了，只陪着。

### 二、老人输入后，整理简化放入独立数据库

老人说：

> 嗯……那个，我我我年轻时候啊，就在纺织厂当挡车工，一天站八个钟头，你说是不是

数据库里存的是（`src/text.mjs` 的 `clean → splitClauses → simplify`）：

| 字段 | 存的内容 |
|---|---|
| 原话 `utterances` | 一字不改留档，可回溯 |
| 主句 `sentences.statement` | **我二十来岁那年在纺织厂当挡车工，一天站八个钟头** |
| 疑问形式 `sentences.asks` | 我那时候在纺织厂是啥情况来着？／我当挡车工的事，你还记得吗？…… |
| 实体 | 地点[纺织厂] · 时间 二十岁上下（"二十来岁"归一化） |
| 其它 | 关键词、置信度、被问过几次、说过几遍 |

**老人说什么，整理简化之后直接存档** —— 不再回头问"我记下了：……没记错吧？"
让他点头。多一道核对，老人要多应付一次，而且他往往记不得自己说过什么，
点了头也不能说明什么。所以砍掉了。

> 早期版本是两档的（待确认 → 老人点头才转正），现在已经没有这一档：
> 记忆进库就是正式档案。老库里遗留的"待确认"会在启动时自动转正一次。

### 二·二、四个维度（按产品说明的"记忆档案库"落库）

产品说明要求"抽取人物/时间/地点/事件"、"模糊时间归一化"、"人物实体合并"，并且记忆档案库要能**按人物 / 时间 / 地点 / 事件四个维度筛选浏览**。所以这四个维度各有自己的表和 id，用关联表挂到"记忆"（一条主句 = 一段记忆）上：

| 表 | 装什么 | 说明 |
|---|---|---|
| `people` | 人物维度 | **实体合并**：`老张` / `张师傅` / `张建国` 归成同一个人（`alias_key`），别名全留在 `aliases` |
| `times` | 时间维度 | **模糊时间归一化**：保留原话（`raw`），同时给出 `label` 与 `from_year`/`to_year` |
| `places` | 地点维度 | 城市 / 厂矿 / 村庄 / 院子 |
| `events` | 事件维度 | 住宿舍 / 分房 / 当兵 / 出嫁 … |
| `person_links` 等四张 | 记忆 ↔ 维度的关联 | 一条记忆挂上它涉及的人物、时间、地点、事件 |
| `sentences` | **记忆本体** | 整理简化后的主句 + 疑问形式 + 置信度 |
| `utterances` | 老人原话 | 一字不改留档 |
| `candidates` | （已废弃） | 核对流程砍掉后不再写入，老数据启动时自动清掉 |
| `topics` | 话题断点 | 上次讲到哪、被回避过几次 |
| `meta` | 人设 | 称呼、字数上限 |

**模糊时间归一化实测**（人设里填了出生年 1948）：

| 老人原话 | 归一成 |
|---|---|
| 小时候 | 1953—1960 年（童年） |
| 年轻时候 | 1966—1973 年（青年） |
| 二十来岁 | 二十岁上下 → 1966—1970 |
| 五十年代 | 1950—1959 年 |
| 文革前后 | 1966 年以前 |
| 八三年 / 1950年 | 1983 年 / 1950 年 |

没填出生年时，只保留原说法并注明"未填出生年，只能保留原说法"，不会瞎猜年份。

#### 语义判断全交给大模型

原来这些判断全是**正则硬判**：

| 判断 | 原来的做法 |
|---|---|
| 这句话在干什么 | `classify()` 几个关键词 |
| 情绪 | `mood()` 负面词 + 叹气次数 |
| 哪儿不舒服 | `healthSigns()` 一列身体部位词 |
| 是不是让岁语干活 | `isRequest()` 枚举动词 |
| 是不是废话 | `isNonContent()` 枚举应声词 |
| 是不是补充细节、补哪一格 | `FRAGMENT` + `detectSlot()` |
| 是不是不想聊了 | `AVOID` 枚举 |
| 值不值得存 | 长度 ≥ 5 |

说法太活了，正则覆盖不全：

```
"我这两天腰不得劲"        → 没命中"腰疼"
"你帮我把窗户关上吧"      → 不是"帮我"开头
"那会儿啊，还没到八八年"  → 不是补细节，是改口
```

现在合成**一个 `understand` 节点**（`src/understand.mjs`），一次模型调用全判完：

```json
{"intent":"tell","memorable":true,"request":false,"correction":null,
 "fragment":false,"slot":"","mood":"flat","health":[],
 "statement":"我年轻时候在国棉三厂当挡车工"}
```

实测：

| 老人说 | 判成 | 入库 |
|---|---|---|
| 我这两天腰不得劲，晚上翻来覆去睡不着 | tell / memorable | 1 条 |
| 你帮我把窗户关上吧 | request=true | 不存 |
| 唉，一个人待着没意思 | mood | 不存 |
| 嗯，知道了 | ack | 不存 |
| 不对，那不是75年，是1976年 | correction | 改进库，不新增 |

**正则全部保留，但只当兜底** —— 没配模型、调不通、或者离线自检的时候走原来那套。
所以 `npm test`（临时目录、没有 `llm.json`、用 `seyo_test` 账号库）仍然是 213 项全过（需要 MySQL 已启动）。

还留在本地的不是"判断"，是"文本处理"：切句 `splitClauses()`、去口癖 `clean()`、
标点归一、实体词表（给检索建索引用）。
#### 说话就进库（踩过的四个坑）

老人说了话、库里却没动静，查下来是**四个 bug 叠在一起**：

**① 身份信息规则把整句吞了**

```js
if (/^(我叫|我的名字|我姓|我小名|我今年|我属|我生日)/.test(statement)) return { action: 'skipped' };
```

`^我今年` 在里面 —— 而"我今年"是老人最常见的开场白之一：

```
"我今年七十八了"            → 整句丢
"我今年七十八，还能自己做饭"  → 也整句丢（后半句明明是正经记忆）
```

收紧成：只在**整句就是个短的身份声明**时才跳过，并且把"我今年"从名单里去掉（年龄是变化的，值得记）。

**② `clean()` 把叠词吃掉了**

```js
s = s.replace(/([\u4e00-\u9fa5])\1{1,}/g, '$1');   // 两个相同汉字就合并
```

本意是去掉口吃（"我我"），但中文叠词太常见：

```
今天天气不错 → 今天气不错
我天天早上…  → 我天早上…
爸爸 → 爸    慢慢 → 慢    看看 → 看
```

改成只合并**三个以上**的（真正的口吃）。

**③ 补主语补到了请求句上**

```
帮我倒杯水 → 我帮我倒杯水
今天天气不错 → 我今天天气不错
```

原来"句子不以我开头就补个我"。现在改成**白名单**：只有以动词/介词开头（确实省了主语的）才补。

**④ 两道闸门都卡太死**

| 闸门 | 原来 | 现在 |
|---|---|---|
| `handleTurn.substantial` | ≥12 字（或 ≥6 且"我"开头） | **≥5 字**，只管"是不是在讲事" |
| `distill` 实体判断 | 有实体 **或** 第一人称讲事 | 再加一条：**够长且在讲事**也算 |

现在两道闸门**各管各的**：一层管"是不是在讲事"，一层管"有没有内容"。

**顺带**：请求句（"帮我倒杯水""把窗户关上"）不算记忆，既不入库、也不当"补充细节"并进上一条
（`isRequest()`）—— 不然会把它并进正在讲的事，把正经记忆改坏。

实测同一批 10 句话，修之前进 2 条，修之后每句都被正确归类：

```
我今年七十八了        ＋ 入库
我孙子叫小明，在城里念书  ＝ 以前记过，合并
今天天气不错          ＋ 入库
我年轻时候在国棉三厂上班  ＝ 合并
帮我倒杯水            （请求，不入库）
你还记得我老家在哪儿吗   （问句，不入库）
```

#### 地点维度里的脏名字

地点名曾经抽出这些：

```
的国棉三厂    京的纺织厂    屋里    门口
```

前两个是正则的问题 —— `([\u4e00-\u9fa5]{2,4}(?:省|市|…|厂))` 里的 `{2,4}` 把虚词也算进字数：

```
"进的国棉三厂" → 从"的"开始匹配 → "的国棉三厂"（脏）
"在北京的纺织厂" → "京的纺织厂"（脏）
```

而且**一旦这样匹配成功，正则就跳过这一段**，正确的"国棉三厂"再也找不到。
改成名字部分**不许含虚词**（`[^…的了过着是在到去回上下不没们地得]{2,4}`），
匹配只能从"国"开始，正好是"国棉三厂"。

改完之后地点维度：

```
国棉三厂 2   纺织厂 2   车间 2   北京 1   城西 1   宿舍 1   厂里 1   屋里 1   门口 1   杭州 1
```

存量的脏数据用 `reextractAll()` 重算一遍就干净了。

#### 规则认不出的，让大模型判

规则表能认"文革""八十年代""年轻时候"这种**明确的说法**，但老人说话常常是**前后一起说**的：

> "我进厂那年刚满二十，一个月挣十八块五，住集体宿舍"
> "那会儿还没结婚呢"
> "过了两年才调回城里"

时间是"那年""那会儿""过了两年"—— 规则认不出绝对年份，整件事就掉进时间轴的**"时间未定"**。
所以回完话之后，会把这一轮新存的句子**交给大模型再判一次**（`judgeTimes`，背景跑，不拖慢回复）：

```
我进厂那年刚满二十      → 1968   （1948 年生 + 20 岁，分毫不差）
我老伴秀兰走了三年了    → 2023   （今年 2026 − 3）
我爹是拉洋车的          → 1956   （1948 年生，童年 8 岁）
我那会儿八个人挤一间宿舍 → 1968   （接着上文判的）
我后来去杭州了          → 1978   （"后来"往后推）
```

**只在缺时间时才问**：已经有年份的、或者 label 里有年份的，一律不动 ——
规则的明确结果比模型猜的可靠。

**判不准也让它给个大概**：童年 → 6~12 岁、青年 → 20~28 岁……
因为时间轴靠年份排序，不给年份就全堆到末尾（"童年时期"排在 2026 后面就很荒唐）。
label 里会写清"大约""前后"。

**但它是个专门抽时间的任务**，提示词里写死了：拿不准就 null，别编。所以像
"我今天挺高兴的"这种没头没尾的，该 null 还是 null。

> 踩到的坑：模型经常输出 **JS 对象字面量**而不是 JSON ——
> `[{i:1,year:1968,label:1968 年前后}]`，键和字符串都不带引号，`JSON.parse` 直接炸。
> 提示词里写了"键必须加双引号"它还是这么回。所以 `agent.mjs` 里有个 `repairJsonArray()`，
> 先给键和裸字符串补引号、收掉尾逗号，再 parse。

手动重跑：`npm run test:timeline`，或者 `POST /api/timeline/judge`。

#### 时间轴的排序：没有年份的也要排进该在的位置

大模型能判出大部分年份，但总有几句判不出来（"杭州开餐馆那几年""是的，买的人老多了"）。
原来的 SQL 是

```sql
ORDER BY (s.year IS NULL), s.year ASC, s.seq ASC
```

`(year IS NULL)` 排在第一位，于是**没有年份的全被踢到最后**：

```
1956 → 1968 → 1969 → 1978 → 2023 → 2026 → 去杭州后中年时期 → 杭州开餐馆那几年 → 时间未定
```

可"杭州开餐馆"明明发生在 1978 年去杭州之后、老伴走之前。这样排，人生顺序全乱了。

现在给每条**算一个排序用的年份**：

| 情况 | 怎么定位置 |
|---|---|
| 有 `year` | 直接用 |
| 没有年份，前后都有 | 按讲述先后（`seq`）**在前后两个已知年份之间插值** |
| 没有年份，只在末尾 | 最后一个已知年份 + 0.1、0.2… 依此类推 |
| 没有年份，只在开头 | 第一个已知年份 − 0.1、0.2… |
| 整库一条年份都没有 | 只能按讲述先后兜底 |

分组不变（按 `time_label`），但每组带一个 `order`，前端按它排。同一组取**组里最早那条**的位置
—— 事情从哪年开始，就排哪年。

效果：

```
1956 → 1968 → 1969 → 1978 → 去杭州后中年时期 → 杭州开餐馆那几年 → 约 1978 年 → 2023 → 2026
```

最后那个"约 1978 年"原来是"时间未定"—— 挂在一个已经算好位置、排在 1978 和 2023 之间的
节点上，读起来自相矛盾。既然位置是推算的，就用"约"把推算年份说出来。

#### 一件事不要摊成好几张卡

大模型给每句话标的时期不一定一样。同一件事会被它标成好几个：

```
1978 年            → 我后来去杭州了
去杭州后中年时期     → 我在那边开餐馆
杭州开餐馆那几年     → 3点就要起来了
约 1978 年          → 是的，买的人老多了
```

明明是同一件事（去杭州开餐馆、半夜起来备货），却摊成四张卡，看着像四件不相干的事。

**第一层：连续没年份的句子，落在同一个点上**

老人是一口气讲完一段往事的："我在那边开餐馆""3点就要起来了""买的人老多了"连着说，
中间没插别的年份。如果按每条在序列里的位置逐条插值，它们会被摊成 1980 / 1982 / 1984 三个点。

所以按**连续的没有年份的段**（run）来算：整段取中点插一次值，段里每条都用这个数 ——
一串连着讲的话本来就属于同一个时期。

**第二层：相邻的卡合并**

满足其一就并：

| 条件 | 为什么 |
|---|---|
| 推算年份相差不到 1 年 | 就是同一年 |
| **两边都没有确切年份** | 都是"某个时期"，本来就说不清，凑一起读比散着读强 |

合并后标签取"更确定"的那个：**确切年份 > 估算年份 > 模糊标签**。

**第三层：让大模型把年份补上**

前两层只是把说不清的凑到一起。真要定位，还是得靠模型 —— 提示词里已经要求
"能看出是哪个人生阶段，也要给个大概年份"（童年 → 6~12 岁、中年 → 40~50 岁……）。

`POST /api/timeline/judge` 或 `npm run test:timeline` 会重跑一遍。

效果：

```
1946 年  1 条   我爸妈在1946年结婚的
1956 年  3 条   童年
1968 年  6 条   国棉三厂
1969 年  2 条   结婚
1978 年  1 条   我后来去杭州了
1988 年  3 条   · 我在那边开餐馆        ← 一件事，一张卡
               · 3点就要起来了
               · 是的，买的人老多了
2023 年  1 条   老伴走了
2026 年  2 条   当下
```
#### 时间轴的样子

**轴在正中间，卡片左右交替** —— 像一条人生长河，事在两岸。

```
   ┌──────────────────────┐
   │ 1956 年          3 条 │
   │ · 我小时候住在城西的剪子巷
   │ · 我娘在家给人缝衣裳  │
   └──────────────────────┘
                          ◉──────┐
                                 │ 1968 年          6 条 │
                                 │ · 我年轻时候在北京……   │
                                 └──────────────────────┘
   ┌──────────────────────┐
   │ 1969 年          2 条 │
   │ · 我老伴叫秀兰，六九年结的婚
   └──────────────────────┘
                          ◇  ← 虚线：位置是推算的
                                 ┌──────────────────────┐
                                 │ 杭州开餐馆那几年  1 条 │
                                 │ · 3点就要起来了        │
                                 └──────────────────────┘
```

- **实心圆点 + 大号年份** = 有确切年份
- **虚线圆点 + 小号灰字** = 位置是按上下文推算的（"中年时期""杭州开餐馆那几年""约 1978 年"）
  —— 一眼能看出哪个是实的、哪个是推的
- 圆点和卡片之间有一小截连接线，卡片压在轴的一侧；卡片头部一条虚线与内容分开

**窄屏（< 760px）自动收回左边单列** —— 手机上左右交替只剩半屏宽，挤成一团没法读。



**按维度浏览**：`GET /api/archive` 给出四维总览；`GET /api/archive?dim=person&id=…` 列出这个人相关的全部记忆（`dim` 换成 `time` / `place` / `event` 同理）。

**数据存在 MySQL**：主库 `seyo` 放账号/会话，每个账号一个 `seyo_u_<id>` 库放这位老人的全部数据。
家人端能看到"数据库：mysql://…/seyo_u_…"和条数；`GET /api/db` 导出一份 JSON 快照（含各表内容），
`POST /api/dump` 另存一份可读 JSON 到 `data/index-<账号库>.json`。数据跟代码分开，升级不覆盖。

#### 家人端：三个页签合成一个「记忆库」

原来家人端有六个页签，其中三个看的是**同一批记忆**：

| 原来的页签 | 看的是 |
|---|---|
| 四个维度 | 记忆，按人/时间/地点/事件分组 |
| 主句库 | 记忆，一张表 |

来回切很累，而且改一处得去看三处。现在合成**一个「记忆库」面板**：

```
记忆库  老人说过的话整理成的记忆。可以搜、可以按人/时间/地点/事件分组看，也能直接改
[搜一句话…        ] [搜索] [全部] [导出 CSV]

└────────────────────────────────────────┘

┌──┬──────────────────┬────────┬──────┬────────┐
```

### 给记忆配照片（时间轴 / 地图浮窗）

时间轴每张卡片、地图上每个地点的浮窗里都有 **＋ 照片**：

- 家人端选图 → 浏览器先把图缩到最长边 1600 → `POST /api/photos`（base64，库里只记文件名，文件在 `data/photos/`）；
- 照片挂在**那条记忆**（`sentences`）上，所以时间轴和地图共用一份：分组怎么合并，图都跟着记忆走，不会丢；
- 老人聊到相关往事时，`/api/chat` 会把那条记忆的照片放进 `photos`，老人端直接显示出来（家人加的照片会"发出来"给他看）；
- 老人直接问"有图片吗 / 有照片吗"也会发：先找当前这件事、最近聊过的几件、检索命中；都对不上就退到库里最近的照片（问照片时不能回"我啥都没有"）；
- 备份只拷 `data/`，记忆和照片一起带走；清空记忆 / 删单条记忆时，照片文件和记录一起删。

> **看图说话（模型识别照片内容）还没接**：现在配的 `deepseek-chat` 是纯文本模型，看不了图。
> 等换成支持看图的接口（通义千问 VL / 智谱 GLM-4V / 本地 Ollama 等）再补"岁语看着照片说一句"。

### 三、老人提到相关内容 → 搜索主句库回答

老人不会总用原话问。实测这几种问法都能答上来：

| 老人问 | 检索到 | 岁语答 |
|---|---|---|
| 我当挡车工那事儿你还记得吗？ | 相关度 1.20 | 我记得呢，我二十来岁那年在纺织厂当挡车工，一天站八个钟头。 |
| 我年轻时候在哪儿上班来着？ | 0.98 | 我记得呢，我二十来岁那年在纺织厂当挡车工…… |
| 我那会儿干活累不累来着？ | 0.42（话题类别） | 您说过，我二十来岁那年在纺织厂当挡车工…… |
| 我以前是干啥工作的来着？ | 0.42（话题类别） | 这个我记着，我二十来岁那年在纺织厂当挡车工…… |
| 我老伴叫啥来着？（库里没有） | 无命中 | 这个我还真没听您说过。……您给我讲讲？ |

**检索自带上下文。** 老人常用短句追问，一句话本身信息不够，所以要合起来看：

* **主判据**：只用老人这一句查（防止"没问过的事"被答上来）
* **辅助**：把**正在讲的这件事**接在后面再查一次，只占 3 成权重，帮得上忙但带不偏
* **不算数的情况**：问"我小学在哪儿念"，而库里只有纺织厂的事 —— 上下文不许顶上，照样老实说记不清
* 之前**问过的问题不进上下文**（提问不是事实，混进来只会让判断跑偏）

打分（`src/store.mjs` 的 `search`，每一项都能在界面上看到）：

```
① 字面片段命中：老人这句话的 3–4 字片段，有多少真的出现在这一条记录里
   满库都有的通用片段（"我在""在纺"）按 0 分计，避免假重合
② 话题类别：问"干啥工作的"，这条讲"挡车工" → 按类别对上
③ 称呼直查：问"老张是谁来着" → 含"老张"的那条优先
④ 关键词 / 人物 / 地点 / 事件 / 问法相似 / 时间 − 反向证据
≥0.45（靠类别命中的 ≥0.40）直接答 ｜ 0.30~0.45 半确定地答 ｜ <0.30 老实说记不清
```

类别词表是通用说法（工作/居住/上学/当兵/婚姻/生育…），**不是编造的记忆**：只有老人真的讲过"挡车工""学徒""种地"这类词，那条记录才会被打上 work 类别。

### 四、不重复记、不编造

* **换种说法讲同一件事会合并**："我年轻时候在纺织厂当挡车工"和上面那条只差时间状语 → 合并计数，不会存成两条（判据：最长公共片段覆盖 + 去掉时间状语后再比）；补进去的年份等信息会并进原记录，不会丢。
* **短句并进正在讲的那件事**：老人说"在北京"、"1950年"、"想起和老张去买苹果"，都会并进当前这件事，不会变成一条条碎句；库里只有"完整的那件事"。
* **半截话不入库**：抽不出人物/地点/时间/事件的碎片直接丢掉。
* **库里没有就说没有**：`这个我还真没听您说过。您年轻时候的事，我还没听您讲过呢，您说说？`

## 网页上能当场看到它干了什么

**👤 账号 → 设置 → 内部过程**（点开）：

* **① 听懂这句** —— 意图、整理出的主句、人物/地点/时间/事件、情绪
* **② 查主句库** —— 命中哪几条主句、相关度多少、每个分项（字面重合/话题类别/关键词/人物/地点/事件/问法/时间）各贡献多少
* **③ 整理入库** —— 这条存成了什么、置信度多少、是新增还是合并
* **④ 库里现在有什么** —— 条数与数据库文件路径，还能点"看主句库"、"试着自己搜一条"
* **⑤ 陪伴守望** —— 摄像头读数、逐条闸门（为什么开口 / 为什么不开口）

**为什么收进设置里**：老人的主界面上只该剩"说话"这一件事。
摄像头、内部过程这些是**家人偶尔才动**的 —— 放主界面上，老人会去点，点了又看不懂。

## 三个页面

| 页面 | 谁用 | 地址 |
|---|---|---|
| **登录 / 注册** | 所有人 | `/login` |
| **对话页** | 老人 | `/` |
| **家人查看端（大屏）** | 家人 / 老人旁边看 | `/family.html` |
| **家人远程端** | 孩子手机 / 另一台电脑 | `/remote.html` |

未登录访问 `/`、`/family.html`、`/remote.html` 都会跳到 `/login`；登录后共用同一个账号的数据。
`/` 和 `/family.html` 之间可以顶部导航互跳；**`/remote.html` 单独存在，和大屏端互不跳转**。
想直接打开某一页签，可以用网址片段：
`/family.html#map`（足迹地图）、`#graph`（人物图谱）、`#meds`（吃药提醒）；
旧网址 `#db` 会自动落到「记忆库」。
对话页加 `?auto=1` 可跳过开场直接进入（触摸屏 kiosk 用）。

## 人设（称呼、字数上限）

`GET/POST /api/persona`，或改数据库 `meta` 表里的 `persona`：

```json
{ "agent_name": "岁语", "self_ref": "小孙子", "elder_call": "爷爷", "birth_year": 1948, "max_chars": 60 }
```

`elder_call` 换成"奶奶/姥爷/妈"时，称呼与语气词会自动跟着变。

## 接口

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/api/auth/register` | 注册并登录（`username` + `password`），返回 HttpOnly 会话 Cookie |
| POST | `/api/auth/login` | 登录 |
| POST | `/api/auth/logout` | 退出登录 |
| POST | `/api/auth/change-password` | 改密码（`oldPassword` + `newPassword`），其它设备会话失效 |
| GET | `/api/auth/me` | 当前登录账号 |
| POST | `/api/chat` | 一轮对话。返回回答、检索命中与分项得分、新入库内容、确认结果、统计 |
| GET | `/api/history?sessionId=&limit=10` | 刷新后恢复最近 N 条对话（不触发开场白） |
| GET/POST | `/api/family/messages` | 家人远程端：查看消息 / 给孩子发一条消息 |
| GET | `/api/family/pending` | 老人端：取还没念过的孩子消息（点赞/回复通知也在这里） |
| POST | `/api/family/ack` | 老人端念完后回执，避免重复念 |
| GET | `/api/daily?date=` | 当天对话总结（没有就生成） |
| POST | `/api/daily/feedback` | 家人对当天总结点赞 / 回复，并通知老人端 |
| POST | `/api/opening` | 主动开口（接续上次 / 首次见面 / 时间轴空缺） |
| GET | `/api/search?q=` | 只做检索，看老人这句话能查到哪条 |
| GET | `/api/sentences` | 主句库全量 |
| DELETE | `/api/sentences/:id` | 删一条 |
| GET | `/api/entities` · `/api/utterances` · `/api/candidates` · `/api/topics` · `/api/stats` | 实体 / 原话 / 待确认 / 话题 / 统计 |
| POST | `/api/reset` | 重置：清空记忆、对话、照片、吃药安排/记录和记事本提醒（可保留人设） |
| GET | `/api/db` | 导出当前账号的 JSON 数据快照 |
| GET | `/api/meds` | 用药安排 + 今天每一顿的状态（later / soon / due / done） |
| POST | `/api/meds` | 加一个药（药名、剂量、每天几个时间） |
| DELETE | `/api/meds/:id` | 删一个药的提醒 |
| POST | `/api/meds/confirm` | 确认某一顿吃过了（`medId` + `slot`） |
| GET | `/api/reminders` | 记事本：未到点的 + 已经到点等确认的提醒 |
| POST | `/api/reminders` | 加一条提醒（`text` + `dueAt` 或 `delayMs`） |
| POST | `/api/reminders/:id/done` | 点「知道了」，标记完成 |
| DELETE | `/api/reminders/:id` | 删一条提醒 |

> 除 `/api/auth/*` 外，所有接口都要登录；未登录返回 `401 { login: true }`。
> 页面 `/`、`/family.html`、`/remote.html` 未登录会 302 到 `/login?next=...`。
